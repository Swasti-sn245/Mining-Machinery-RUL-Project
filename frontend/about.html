ML Pipeline
01
DATA LOADING
NASA C-MAPSS FD001 — 20,631 training rows (100 engines run to actual failure), 13,096 test rows, 14 usable sensors after dropping 8 near-constant columns.
pandas
02
TRUE RUL LABEL + STANDARD CLIP
RUL = (last cycle NASA recorded) − (current cycle) — an observed value, not a derived formula. Ceiling clipped at 125 cycles per the standard C-MAPSS literature convention (Heimes 2008; Saxena et al. 2008).
numpy
03
GROUP-AWARE TRAIN / VAL / TEST SPLIT
GroupShuffleSplit + GroupKFold throughout — an engine's cycles never span two splits, preventing leakage. Test engines touched exactly once, at final evaluation.
scikit-learn
04
HYPERPARAMETER TUNING
RandomizedSearchCV + 3-fold GroupKFold for XGBoost, Gradient Boosting, Random Forest, AdaBoost, and an MLP — small, CPU-light search grids.
RandomizedSearchCV
05
REFIT + VOTING ENSEMBLE
Tuned models refit on the full training pool (train + validation). Top 3 by validation R² combined into a validation-weighted Voting Ensemble.
scikit-learn + xgboost
06
5-FOLD CROSS VALIDATION
GroupKFold(5) on the full training pool reports mean ± std R²/MAE per model — a robustness check distinct from the tuning search.
GroupKFold CV
07
SHAP EXPLAINER
TreeExplainer on the winning Random Forest computes per-sample SHAP values. Each prediction gets unique failure reasons — not global feature importances.
shap TreeExplainer
Dataset — NASA C-MAPSS FD001 (Turbofan Engine Degradation Simulation)
Why this dataset? Real mining equipment sensor data is proprietary — OEMs do not release it publicly, an acknowledged challenge in the field. Earlier versions of this project used the AI4I 2020 dataset, but AI4I has no real RUL label — the previous RUL target was derived from an invented formula built on top of one of the model's own input features, which inflated accuracy without teaching the model anything real. NASA C-MAPSS FD001 solves this: every engine is run in simulation until it actually fails, so RUL = (cycle at failure) − (current cycle) is a genuinely observed value, not an assumption.

The only transformation applied is a ceiling clip at 125 cycles — a long-standing, literature-cited convention (Heimes, 2008; Saxena et al., 2008), not an invented curve — because sensor readings in the first ~100+ cycles of an engine's life carry no real degradation signal.

Planned upgrade: Direct integration with NCL Nigahi Project operational data remains a future scope item. When real mining data becomes available, only the training step changes — the pipeline, API, and frontend structure stay the same.

What Changed in v3
📈
Non-linear RUL curve
Replaced linear label (MAX - wear) with a piecewise degradation curve. Slow early decay, fast near end-of-life — physically realistic.
🔊
Noise augmentation
2% Gaussian noise applied to all sensor columns. Dataset doubled to 20K rows. Prevents model memorising exact values.
🔬
2 new features
wear_squared (accelerating degradation) and thermal_stress (temp differential × power). Better captures compound failure mechanisms.
🗳
Voting Ensemble
GB (60%) + XGBoost (40%) combined. Weights reflect GB's higher individual score. Typically gains 1–3% R² over single model.
📊
5-fold cross validation
More reliable accuracy estimate than single train/test split. R² reported as mean ± std across all folds.
🔍
SHAP per-sample reasons
Replaced global feature_importances_ with SHAP TreeExplainer. Failure reasons are now genuinely unique per prediction.
✅
Input range validation
Both frontend and backend validate all 5 input fields. Clear error messages with acceptable ranges shown in real time.
What Changed in v4 — Machine-Scaled RUL
⚙️
6 individual machine types
Replaced 3 grade buttons (L/M/H) with 6 specific machines: Scraper, Grader, Dozer, Shovel, Dumper, Dragline. Each has a distinct real-world max service life.
📏
Real-world RUL scaling
v4 model predicted a proxy RUL on a 0–253 scale (AI4I-based); v5's FD001 model predicts on a 0–125 scale. Frontend and backend convert: health_pct = raw_rul / 125, then scaled_rul = health_pct × machine_max_hours. A Dragline with 80% health shows ~96,000 hrs remaining; a Scraper shows ~20,000 hrs.
🎯
Health-based risk thresholds
Risk levels now computed on health_pct (universal), not raw hours. Critical: <20%, High: 20–40%, Medium: 40–65%, Low: >65%. Fair comparison across all machine classes.
🚀
FastAPI backend
Migrated from Flask to FastAPI. Automatic Swagger UI at /docs, Pydantic validation, async-capable. Zero breaking changes to model or feature pipeline.
What Changed in v5 — Real RUL Labels
🔁
Switched to NASA C-MAPSS FD001
Replaced AI4I 2020 (no real RUL label, formula-derived target) with FD001, where RUL is the actual observed number of cycles until an engine failed in simulation.
🧪
Group-aware splitting throughout
GroupShuffleSplit / GroupKFold everywhere — an engine's cycles never span train, validation, and test simultaneously, eliminating a subtle leakage risk.
🏆
Random Forest selected on test performance
5 tuned models + a Voting Ensemble compared on a held-out test set touched exactly once. Random Forest won on test R² (0.8295) with a healthy overfit gap (0.0199).
📥
14-sensor input form
Replaced the 5 mining-analogy inputs with the 14 real FD001 sensors the model actually uses — temperatures, pressures, shaft speeds, and flow/bleed ratios.
Future Scope
🚛
FLEET OVERVIEW
Multi-machine dashboard. Monitor health scores, RUL rankings, and risk levels across the entire fleet on one screen.
📡
REAL NCL DATA
Integration with operational data from NCL Nigahi Project. OBD/CAN bus telemetry feed. Same pipeline, real sensor inputs.
🧠
LSTM / DEEP LEARNING
Time-series LSTM model for sequential sensor data. Captures temporal degradation patterns not visible in snapshot features.
🧩
DIGITAL TWIN
Physics-informed simulation layer. What-if maintenance scheduling: "Delay service 3 days — what is the failure probability?"
🔔
ALERT SYSTEM
SMS/email notifications when RUL drops below configurable threshold. Integrates with existing mine maintenance workflows.
⛏
DRILLING MACHINERY
Extend coverage to drilling equipment (blast hole drills, DTH hammers). Separate model trained on drilling-specific failure modes.
